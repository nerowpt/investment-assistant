## 一、一句话定位

> **一个以 LLM 为深度分析协作者的个人投资决策辅助系统，覆盖"选股 → 建仓 → 持仓巡检 → 卖出"全流程，长线为主、热点为辅。**

## 二、用户画像（仅一人，但写清楚仍很重要）

| 维度 | 描述 |
|---|---|
| 角色 | 普通散户，有 6+ 年实盘经验 |
| 资金量 | 个人级（非机构） |
| 投资风格 | **长线价值投资为主 + 部分仓位博弈板块轮动 / 热点** |
| 持有周期 | 主仓 1-3 年+，波段仓 1 个月-1 年 |

| 现有工作流 | 每月/每季手动复盘 + 与 AI 反复对话获取深度分析 |

## 三、核心价值主张

### 这个产品 **能做** 什么（差异化优势）

1. **深度逻辑巡检自动化**：定期对持仓做"逻辑是否破坏"的体系化判断，输出与人对话级别的报告（替代每次重复几小时的 AI 对话）
2. **AI 原生协作**：通过 MCP 协议直接对接 Cursor / Claude Desktop，让 LLM 调用结构化工具完成"取数 → 推理 → 报告"全链路
3. **长线 + 短线双层视角**：主仓走长线巡检，副仓走热点扫描，一套系统两层逻辑
4. **持仓上下文记忆**：系统记住你的持仓、成本、调仓历史、上次巡检结论，AI 不需要每次重新被告知背景
5. **散户友好的成本结构**：复用 Cursor 订阅（无需额外 LLM 费用）+ 免费数据源 + AI 抓实时叙事

### 这个产品 **不做** 什么（边界）

1. ❌ 不做实时行情看盘（同花顺/雪球已经做得很好）
2. ❌ 不做技术指标交易（高频/超短不在用户风格内）
3. ❌ 不做自动下单（决策权完全在用户）
4. ❌ 不做组合管理 / 风险归因 / 业绩归因（机构级功能，散户用不到）
5. ❌ 不做社区 / 分享 / 跟单（仅自己用，无社交属性）
6. ❌ 不做付费订阅 / 用户系统（仅自己用）

## 五、五大核心设计原则

### 1. AI-Native，不是 AI-Wrapped

**含义**：AI 不是产品的"功能"，而是产品的"协作者"。
**实现**：后端的核心能力以 **MCP Tools** 形式暴露，让 LLM 可以像调用函数一样调用「取持仓」「跑巡检」「查最新研报」「估算异环流水」。
**反面教材**：在产品里塞一个聊天框，让用户问问题——这是 AI-Wrapped，不是 AI-Native。

### 2. 决策权 100% 在用户

AI 输出分析、概率、场景、风险点，但**不发出"买/卖"指令**。
所有"买卖建议"必须以"四象限分类"形式呈现（低估逻辑还在 / 价值陷阱 / 等风格切换 / 逻辑已破坏），让用户自己做最终决定。

### 3. 上下文持久化优先

系统必须记住：
- 当前持仓 / 成本 / 仓位
- 历次巡检结论
- 用户对每个标的的"个人逻辑"（你买这个的核心理由）
- 上次讨论中已经达成的判断

这样 AI 每次工作都基于完整上下文，而不是从零开始。

### 4. 数据轻、推理重

不在数据采购上烧钱（个人散户不必要），把"质量"压在 AI 推理 + Web 实时检索上。
关键约束：**数据要够用就行，但 AI 工具集要足够强大**。

### 5. 文档驱动开发

每个功能在写代码前先有文档（场景 → 设计 → 接口）。这是因为：
- 仅一人开发，不能靠"口口相传"
- 长期演进的项目，文档是唯一可靠的"项目记忆"
- AI 协作开发时，文档是给 AI 的最佳 brief

## 六、与现有工具的差异化对比

| 工具 | 强项 | 弱项 | 我们做不做 |
|---|---|---|---|
| **同花顺 / 东财 / 雪球** | 实时行情、社区、基础数据 | 无个性化巡检、无 AI 深度推理 | 行情我们不做，巡检/AI 是我们的核心 |
| **直接用 Cursor / ChatGPT 对话** | 灵活、AI 强 | 没有持仓上下文，每次重复输入；数据需手动喂；无定时任务 | **正是要解决的痛点** |
| **Wind / iFinD** | 数据全、专业 | 贵（机构级）、上手成本高 | 不抢机构市场 |
| **量化平台（聚宽/米筐）** | 回测、自动化 | 偏短线/技术面，不适合长线 | 不做量化 |
| **Bloomberg Terminal** | 全球级数据 + 终端 | 5 万美元/年 | 反向参考的对象 |

**我们的独特生态位**：**「散户能用得起的、以 AI 为核心的、长线 + 热点双视角的、个人投资上下文中枢」**

## 七、核心场景预览（详细设计在 02 号文档）

四大核心场景，按用户提出的顺序：

### 场景 1：选股
- **长线**：板块基本面扫描 → 候选池筛选 → 候选标的深度评估
- **短线**：热点事件抓取 → 受益标的关联 → 弹性评估

### 场景 2：建仓时机
- **长线**：估值低分位 + 基本面拐点 + 资金面（机构持仓变化）
- **短线**：催化事件触发 + 量价信号

### 场景 3：动态持有（持仓巡检）
- **逻辑巡检**（核心 MVP 候选）：定期/事件触发，输出"四象限"判断
- **关键指标监控**：财报披露、研报变化、行业数据、政策

### 场景 4：卖出时机
- **长线**：逻辑破坏 / 估值过热 / 风格切换
- **短线**：止盈 / 止损 / 题材熄火

每个场景下，AI 通过 MCP 工具拉取数据，组合形成深度分析。

## 八、MVP 范围（已确认）

### MVP = **「持仓管理 + 逻辑巡检 + 热点扫描」**（长短双引擎）

> ✅ 决策来源：第三轮 Q9。用户在 PM 推荐基础上扩展了"热点扫描"模块。

**MVP 包含的三个核心模块**：

#### 模块 1：持仓管理（Portfolio）

- 用 YAML/CSV 文件维护持仓（成本、数量、买入时间、个人逻辑、目标价、止损线）
- 支持长线主仓与热点副仓的标签区分（`type: core | swing`）
- CLI 命令：`inv portfolio show / add / update / remove / sync`
- MCP Tool：`get_portfolio`、`get_position_detail`、`get_position_history`

#### 模块 2：逻辑巡检（Inspector）

- **场景**：定期 / 财报后 / 关键事件后，对持仓做"逻辑是否破坏"判断
- **输出**：四象限分类报告（低估逻辑还在 / 价值陷阱 / 等风格切换 / 逻辑已破坏）
- **核心数据维度**：行业 ROE、自由现金流、市场份额、核心叙事、估值分位
- CLI 命令：`inv inspect --target=all | --target=600519`
- MCP Tools：`fetch_financial_report`、`fetch_research_reports`、`compute_valuation_metrics`、`run_logic_inspection`
- 报告输出为 Markdown 文件，可邮件推送

#### 模块 3：热点扫描（Hotspot Scanner）

- **场景**：每日扫描市场热点话题/题材，输出受益标的候选池
- **数据源**：东财涨停板、雪球热度榜、股吧/淘股吧热帖、Web Search 抓取产业新闻
- **AI 工作**：从热点 → 关联受益标的 → 评估弹性 / 估值 / 短期催化
- CLI 命令：`inv scan --period=today | --period=week`
- MCP Tools：`fetch_hot_topics`、`map_topic_to_stocks`、`evaluate_swing_potential`
- 输出每日"候选池"列表，用户决定是否进入持仓

### MVP 不包含（明确放到 V2+）

- ❌ Web 可视化仪表盘（V2，MVP 先用 CLI + Markdown 报告）
- ❌ 选股引擎（V2，更复杂的板块基本面扫描）
- ❌ 自动建仓时机检测（V2）
- ❌ 卖出信号自动推送（V2，MVP 仅在巡检中给"逻辑已破坏"的判断）
- ❌ 移动端 App（V3+）
- ❌ 回测引擎（不在产品边界内）

### MVP "最小可用" 验收标准

完成 MVP 即意味着以下三个工作流可以跑通：

**工作流 A — 长线巡检**
1. 在 `portfolio.yaml` 中维护持仓
2. 在 Cursor / Claude Desktop 中通过 MCP 调用 "巡检我的持仓"
3. AI 调用后端工具，自动拉取最新财报 / 研报 / 网络叙事
4. 输出与"近三天对话"同等深度的 Markdown 报告，落盘并邮件推送

**工作流 B — 热点扫描**
1. CLI 触发 `inv scan --period=today`，或定时任务每日 17:00 自动跑
2. 系统抓取当日热点话题，用 AI 关联受益标的
3. 输出"今日候选池"Markdown 报告
4. 用户在 Cursor 中可继续追问 "深度分析候选池中的某只标的"

**工作流 C — 持仓与巡检的联动**
1. 巡检判定某标的"逻辑已破坏"或"等风格切换"
2. 系统将该判定写入持仓的"巡检历史"字段
3. 下次巡检时，AI 能看到上次的判定，做对比分析（不重复造轮子）

### MVP 工期估计

> 参考量级，非承诺。按"业余时间开发"估算：
>
> - 模块 1（持仓）：1-2 周
> - 模块 2（巡检）：3-4 周（核心难点在 AI 工具集设计）
> - 模块 3（热点）：2-3 周
> - **合计 6-9 周**（业余时间，每周 10-15 小时）

### MVP 范围扩展（vs 原 PM 推荐）的影响

| 维度 | 原推荐（巡检 + 持仓） | 现 MVP（巡检 + 持仓 + 热点） |
|---|---|---|
| 工期 | 4-6 周 | 6-9 周（+2-3 周） |
| 数据源复杂度 | 中（财报/研报） | 高（财报/研报 + 涨停/热度/新闻） |
| MCP 工具数量 | 8-10 个 | 13-16 个 |
| 价值密度 | 单核心场景 | **双引擎，覆盖你实际操作的全部主动决策** |

**结论**：扩展是合理的，因为热点扫描和巡检共享底座（数据接入、AI 工具、MCP Server、报告引擎），新增工作量主要在数据采集器和 2-3 个新 MCP 工具。

## 九、技术栈基线（已确认）

### 编程语言：Python + Go 混合架构

> ✅ 决策来源：第三轮 Q10

```
┌──────────────────────────────────────────────────────────┐
│                  外部入口（用户/AI）                       │
│   CLI    Cursor (MCP)    Web UI(V2)    定时调度          │
└────────────────────┬─────────────────────────────────────┘
                     │  RESTful / gRPC / MCP
                     ▼
┌──────────────────────────────────────────────────────────┐
│   Go 后端（core-server）                                  │
│   - HTTP/gRPC API                                        │
│   - MCP Server                                           │
│   - 持仓状态管理（读写 YAML/CSV）                          │
│   - 调度器（定时跑巡检/扫描）                              │
│   - 报告引擎（生成 Markdown，触发推送）                    │
└────────────────────┬─────────────────────────────────────┘
                     │  本地 gRPC / HTTP
                     ▼
┌──────────────────────────────────────────────────────────┐
│   Python 数据/分析层（data-worker）                       │
│   - AKShare / Tushare 数据采集                            │
│   - 雪球/东财/股吧爬虫                                     │
│   - pandas 财务计算                                       │
│   - Web Search 适配（联网取实时叙事）                      │
└──────────────────────────────────────────────────────────┘
```

**这个分工的理由**：
- **Python**：金融数据生态王者（AKShare/Tushare/efinance），pandas 财务计算，beautifulsoup 爬虫
- **Go**：你的日常工作语言，强类型保证后端稳定性；MCP 官方有 Go SDK；调度器/HTTP/gRPC 性能好
- **不混入彼此领地**：Python 不做对外 API（避免 FastAPI 与 Go 重复），Go 不做数据爬取（避免在 Go 里写 BeautifulSoup）

### 持仓数据存储

> ✅ 决策来源：第三轮 Q11

- 主存储：**`portfolio.yaml`**（手动维护，Git 版本管理友好）
- 历史与巡检结果：**SQLite**（本地数据库，零部署成本）
- 设计原则：**人类可读 > 数据库便利**（仅自己用，YAML 比 SQL 更直观）

`portfolio.yaml` 示例结构（草案）：

```yaml
positions:
  - code: 002624
    name: 完美世界
    type: swing                    # core | swing
    cost_price: 17.00
    shares: 10000
    entry_date: 2026-04-30
    investment_thesis: |
      博弈异环全球化，PC占比65%，渠道分成结构远优于世纪华通。
      目标：净利兑现18-20亿 → PE修复至30倍 → 翻倍。
    target_price: 36.00            # 翻倍止盈位
    stop_loss: 12.00               # 异环若衰减的减仓位
    inspection_history: []         # 由系统自动追加
```
