## 一、一句话定位

> **一个把投资决策流程产品化、把投资行为数据化、把投资经验个人化、把市场叙事可观察化的「执行规范、复盘与个人知识积累系统」。覆盖"研究 → 选股 → 建仓 → 持仓巡检 → 卖出 → 复盘"全生命周期,长线为主、热点为辅。AI 是数据秘书与复盘陪练,不是决策者。研究素材池是用户独有的、随时间复利增长的个人投资资产。叙事周期信号包是反偏见工具,不是水晶球。**

### v0.4 → v0.5 的核心增量

v0.5 不改变 v0.4 骨架,而是**在 M4 监控和 M5 复盘上各嵌一个子模块**,补齐"叙事周期识别"能力:

| 加强方向 | v0.4 | v0.5(当前) |
|---|---|---|
| **叙事周期前瞻识别** | 缺失(只看个股财报和板块涨跌) | **M4 新增"叙事信号包"子模块**(六维度信号矩阵: 基本面/产业链/资金面/关注度/估值/价格行为,客观汇集 + 历史可比案例检索, 用户判断阶段) |
| **错过模式学习** | M5 只有错误模式扫描(已买的复盘) | **M5 新增"叙事错过模式扫描"**(扫你没买但涨 80%+ 的板块, 反推信号何时共振, 反查 L1 是否有线索) |
| **巡检方法论扩展** | baseline-03 四层(宏观/行业/公司/市场) | **新增"第 5 层 叙事周期"**, 与原四层并列 |

> 🎯 **关于"叙事识别"的本质判断(必读)**:
> 这是**反偏见工具,不是水晶球**。事后看 2025 年的中际旭创信号清晰,事前同样有强信号的标的有几十个。
> 价值不在于"准确预测",而在于:
> 1. 把"我没看到"变成"我看到了但选择不上车"(后者的复盘价值远大于前者)
> 2. 强制多维度共振判断,避免"听了个故事就买"
> 3. 通过 L1 长期积累,识别自己反复错过的模式
> 4. 倒逼 thesis 升级(六维共振而 thesis 还停留在"低估值"时,是 thesis 进化信号)

### v0.3 → v0.4 的核心增量(保留)

v0.4 不否定 v0.3,而是**在 v0.3 骨架之上做了三处加强**:

| 加强方向 | v0.3 | v0.4 |
|---|---|---|
| **数据资产化** | 数据每次现取,用完即弃 | 新增 **L1 研究素材库**(自动入库 + 手动录入 + 跨决策长期复用) |
| **风险管理** | 完全缺失 | 新增 **M7 风险护栏**(仓位规则 + 个人禁区 + [二期]回撤/集中度) |
| **流程完整性** | 选股环节较粗 | M1 状态机明确独立 `watching` 子状态(观察池机制) |
| **决策心理纪律** | 没有 | Checklist 加 `emotion_tag` 字段(枚举,记录决策时情绪) |
| **市场状态感知** | M6 只覆盖短线机会 | M4 监控吸收"市场状态画像 + 板块异动告警"(主仓刚需) |
| **数据可信度** | 仅原则提及 | 升级为架构级硬约束: source + tier(S/A/B/C/D) + timestamp,决策快照禁止覆盖 |
| **工期与节奏** | 一次性 13-18 周 | 拆二期: **MVP-1(12-15 周,跑通决策闭环) + MVP-2(10-14 周,增强能力)** |

### 与 v0.2 定位的根本差异(v0.3 起就已确立,v0.4 保持)

| 维度 | v0.2(已废弃) | v0.3 / v0.4 |
|---|---|---|
| 产品骨架 | 以 LLM 为深度分析协作者 | 以**用户自己的执行流程 + 个人数据资产**为骨架 |
| 价值来源 | AI 的判断质量 | **流程规范度 + 数据可追溯度 + 复盘彻底度 + 素材积累深度** |
| AI 角色 | 协作者(参与决策) | **数据秘书 + 复盘陪练**(不参与决策、不写结论) |
| 风险敞口 | AI 出错 → 产品价值坍塌 | AI 出错 → 产品依然完整可用 |
| 真正解决的痛点 | "AI 不够强" | **"自己的执行不规范、复盘不彻底、研究素材没沉淀"** |

> ⚠️ **方向转向的依据**: 用户已识别"AI 财经分析存在高级幻觉"的本质风险(见 baseline-05)。
> 当前可用的 LLM 在金融领域存在严重的幻觉风险:**编出来的研报数据看起来无比专业,但可能是错的,且用户无法即时验证**。
> 金融决策的容错率极低(错一个判断可能损失几万到几十万),AI 错误反馈周期极长(3 个月到 3 年),
> 因此**不能把产品的核心可靠性绑定在 AI 的判断力上**。详见第四轮、第五轮决策日志(`00-讨论历史与决策日志.md`)。

## 二、用户画像（仅一人，但写清楚仍很重要）

| 维度 | 描述 |
|---|---|
| 角色 | 普通散户，有 6+ 年实盘经验 |
| 资金量 | 个人级（非机构） |
| 投资风格 | **长线价值投资为主 + 部分仓位博弈板块轮动 / 热点** |
| 持有周期 | 主仓 1-3 年+，波段仓 1 个月-1 年 |
| 信息能力 | 能看懂财报、研报，理解估值与产业逻辑 |
| 痛点 | 1. **执行不规范**: 买卖凭直觉,事后想不起当时的判断依据<br>2. **复盘不彻底**: 账户亏赚知道,但说不清是哪个环节的错<br>3. **风险管理零散**: 没有仓位规则、个人禁区、回撤护栏等明确约束(v0.4 新增识别)<br>4. **研究素材未沉淀**: 看过的资料、收藏的文章、跟踪的大牛观点散落各处,3 个月后找不到(v0.4 新增识别)<br>5. **错过新叙事周期**: 长线被低估值板块"等"了多年,错过科技牛 — 本质是 **"用长期掩盖错误" + "无法识别产业新叙事的早期信号"** 双重失效(v0.5 把"叙事识别能力缺失"显式拆出来)<br>6. 无法持续做深度的逻辑巡检(信息量大,时间不够)<br>7. **AI 不可靠**: 现有大模型在金融领域幻觉严重,难以即时验证 |
| 现有工作流 | 每月/每季手动复盘 + 与 AI 反复对话获取深度分析(但分析过程未沉淀、结论难追溯,研究素材也未结构化保存,叙事拐点也无系统化捕捉机制) |

### 痛点的本质重定位（v0.3 关键调整）

v0.2 把痛点理解为"AI 没替我做够分析"——这是错的。

v0.3 重新理解为：

> **痛点不是"AI 帮我不够"，痛点是"我自己执行的不够规范、复盘的不够彻底、经验沉淀的不够系统"。**

用户已有 6+ 年实盘经验，能看懂财报、研报，理解估值与产业逻辑——**判断力本身不缺**。
真正缺的是把判断力**纪律化、记录化、可复盘化**的工具。

## 三、核心价值主张

### 这个产品 **能做** 什么(六大差异化价值,v0.5 在 v0.4 基础上扩为 6 大)

#### 1. 决策规范化（Decision Discipline）

> **每个决策动作都有强制 Checklist**，避免随性决策、避免遗漏关键维度。

- 买入前必填：thesis（买入逻辑）、目标价、止损/减仓线、反转条件、机会成本对比（vs 沪深300/中证科技）、置信度、已识别风险点
- 持仓巡检必填：四维度判断（行业 ROE / FCF / 市占 / 核心叙事）、与上次对比、与原 thesis 对比
- 卖出前必填：卖出原因分类（逻辑破坏 / 估值过热 / 止盈 / 止损 / 换股 / 风格切换 / 其他）、本笔收益归因、教训沉淀

**Checklist 引擎拒绝"留白"**：填不完整就保存不了,强制思考。

#### 2. 执行可追溯(Full Traceability)

> **每笔交易的完整生命周期 + 决策当时的依据 + 当时的市场环境快照**,全部存档可追溯。

- 决策日志(Journal):每个买入/调仓/卖出动作都生成一条不可篡改的记录
- 决策当时的依据快照:数据(来自哪里)、推理(基于什么)、结论(置信度多少)、反转条件
- 市场环境快照:决策当天的指数水位、板块估值分位、宏观流动性指标
- 与持仓的双向链接:某次决策对应哪只标的、某只标的的所有历史决策一键回看

**核心理念**:你今天的决策,3 年后再翻出来,所有上下文还原成原样。

#### 3. 复盘个人化(Personalized Learning Loop)

> **用你自己的真实收益,反向校验你的判断模式,识别你的认知盲区**。

- 周期性复盘报告(月/季/年):每笔已平仓交易的收益归因
- 错误模式扫描:识别你在历史决策中反复出现的偏差(例如"低估值陷阱"出现 N 次、"过早卖出成长股"出现 N 次)
- Thesis 校验:对每个"已被时间验证"的持仓,对比当初 thesis 与实际发展
- 个人化检查项沉淀:把识别出的常犯错误,沉淀为下次 Checklist 的强制项

**这是产品真正的护城河**:通用 AI(Cursor/Claude)不知道你的历史,但你的执行日志独一无二。

#### 4. AI 作为数据秘书与复盘陪练(AI as Assistant, Strictly)

> AI **只做信息处理,不做结论性判断**。这是 v0.3 起与 v0.2 最大的差异。

| AI 的允许动作 | AI 的禁止动作 |
|---|---|
| ✅ 拉取财报、研报、新闻原文 | ❌ 给"逻辑是否破坏"的最终判断 |
| ✅ 按四象限模板填**事实部分**(行业 ROE 数据、FCF 数据等) | ❌ 给四象限的**分类结论**(用户自己选) |
| ✅ 汇总热点新闻 + 列出相关标的清单 | ❌ 评估"哪只标的会涨"或"弹性多大" |
| ✅ 提示"上次你在类似 PE 水平买入,最后亏了 X%" | ❌ 给"加仓"或"减仓"建议 |
| ✅ 复盘时帮你扫描错误模式 | ❌ 编造数据、研报、传闻、产业节奏 |
| ✅ 把信息格式化、结构化、可视化 | ❌ 用"长期看会回归"等模糊措辞绕过具体测算 |
| ✅ 从 L1 研究素材库检索相关资料(v0.4 新增) | ❌ 把检索结果加工成"投资建议"输出 |

**架构层硬约束**: 产品的所有"结论性输出"字段(分类、行动建议、置信度)必须由**人类用户**填写,系统不接受 AI 直接写入。

#### 5. 研究素材资产化 + 风险护栏内化(v0.4 新增)

> v0.4 关键认知: **投资能力 = 决策纪律 + 复盘深度 + 研究素材深度 + 风险约束强度**。
> v0.3 解决了前两项,v0.4 补齐后两项。

**5.1 研究素材资产化(L1 研究素材库)**

- **自动入库**: 拉过一次的财报、公告、研报、价格序列等永久保存,不再重复爬
- **手动录入**: 调研纪要、付费研报、雪球深度帖、关注大牛的观点、个人笔记全部入库
- **元数据标准**: 每条素材带 `source / tier(S/A/B/C/D) / timestamp / related_stocks / tags / author / content_type`
- **跨决策复用**: 同一份资料可被多次 Checklist / 巡检 / 复盘引用,而非每次重新查找
- **长期跟踪能力**: 1-3 年后回看,谁的判断长期靠谱、哪类信息源对你最有价值,数据驱动地识别

> **这才是真正的"个人化 AI"**: 通用 AI 不知道你的研究历史,你的素材库**独一无二**。
> AI 在协作时通过 MCP 工具检索 L1,基于你过去的素材给"参考材料",而非凭训练记忆瞎说。

**5.2 风险护栏内化(M7 风险护栏)**

- **仓位规则**: 单标的最大仓位 / 单板块集中度上限 / 整体仓位水平(MVP-1)
- **个人禁区清单**: 不投我不懂的行业 / 不报复性加仓 / 不在恐慌时止损 等(MVP-1)
- **机会成本跟踪**: 每只持仓 vs 沪深300/中证科技 的累计差距告警(MVP-2)
- **回撤告警**: 整体账户 / 单标的的最大回撤监控(MVP-2)
- **强制例外说明**: 触发规则/禁区时,必须写"为什么这次例外",记入 Journal,复盘时统计"例外的实际收益"

> 这是产品对 baseline-01 中"对单产品依赖型公司主动控制"理念的**机制化承载**,以及对 baseline-05 中"低估机会成本是核心陷阱"的**产品级反制**。

#### 6. 叙事周期可观察化(v0.5 新增)— 反偏见工具,非水晶球

> v0.5 关键认知: **散户长期错过新叙事(如 AI/算力/出海)的根因是"叙事拐点不可观察",而非"我不够聪明"**。
> 把叙事拐点的客观信号体系化呈现,把"我没看到"变成"我看到了但选择不上车",后者的复盘价值远大于前者。

**6.1 叙事信号包(嵌入 M4 监控的高阶子模块)**

- **六维度信号矩阵(全部可量化,客观汇集,AI 不下结论)**:
  - 维度 A 基本面: 业绩超预期/收入结构/毛利拐点/在手订单/客户结构/研发产出
  - 维度 B 产业链: 上游订单/行业 CapEx/技术节点切换/**海外同业预演**(科技股关键先导)
  - 维度 C 资金面: 公募持仓环比/北向/龙虎榜/ETF 流向/大宗交易/高管增减持
  - 维度 D 关注度: 卖方研报数量/媒体提及/雪球热度/调研频率/百度指数
  - 维度 E 估值: PE/PB/PS 分位/PEG/vs 同业溢价折价
  - 维度 F 价格行为: 距上次新高时间/成交量异动/超额收益变化/突破形态
- **历史可比案例检索**(L1 价值最大化体现): 系统从 L1 检索"过去出现过类似信号组合的案例 + 后续走势",**不下"这次也会一样"的结论**
- **用户必填阶段判断**: 强制必填字段 `narrative_stage`(萌芽/验证/加速/主升/共识/衰退),且必须引用六维信号中至少 3 项作为理由

**6.2 叙事错过模式扫描(嵌入 M5 复盘助手的子能力)**

- 周期性扫描全市场过去 12 个月涨幅 > 80% 的板块/个股
- 排除已持仓 + 观察池中的 = "你错过的"
- 对每个错过案例反查: 涨之前 6 个月六维信号何时共振 / L1 中是否已有相关线索 / 与你能力圈与个人禁区的关系
- 长期沉淀: **你个人的"错过模式画像"**(总是错过哪类叙事 / 覆盖盲区在哪些行业 / 哪些"个人禁区"实际代价高昂)
- 输出可能反向修改 `personal_redlines.yaml`(经用户确认)

**6.3 严格的"反偏见工具"定位**

- ❌ **不**编叙事故事(AI 在这里幻觉风险最高,绝对禁止)
- ❌ **不**评估"这只标的会涨多少"
- ❌ **不**给"现在是验证期可以买"类结论
- ✅ 只汇集客观可量化信号
- ✅ 强制多维度共振(单维度异常不足以下结论)
- ✅ 用户基于信号矩阵自填阶段判断 + 反转条件

> **本质判断**: 这是"反偏见工具",不是"水晶球"。事后看 2025 中际旭创信号清晰,事前同样有强信号的标的有几十个,最终走出来的只有少数,**有运气成分**。
> 这个定位必须在所有相关报告/CLI 输出中明确写出,否则会被误用。

### 这个产品 **不做** 什么(边界,v0.5 微调)

1. ❌ 不做实时行情看盘(同花顺/雪球已经做得很好)
2. ❌ 不做技术指标交易(高频/超短不在用户风格内)
3. ❌ 不做自动下单(决策权完全在用户)
4. ❌ 不做组合管理 / 风险归因 / 业绩归因的**机构级深度**(基本仓位规则 + 机会成本跟踪 v0.4 已涵盖,深度归因不做)
5. ❌ 不做社区 / 分享 / 跟单(仅自己用,无社交属性)
6. ❌ 不做付费订阅 / 用户系统(仅自己用)
7. ❌ **不让 AI 直接下结论**(v0.3 起): 任何"分类/行动建议/是否破坏"等结论性字段,必须由用户填写
8. ❌ **不做"AI 自动巡检报告生成"**(v0.3 起): AI 可以填事实部分,但分类与判断必须用户参与
9. ❌ **不做日级短线热点推荐 / 涨停板 AI 解读**(v0.4 明确): M4 监控只发"市场状态画像 + 板块异动信号",M6 候选池只做"事件驱动 + 信息汇总",**不做"今天买什么"类输出**
10. ❌ **不让 AI 决定"应该买什么价"**(v0.4 明确): 估值辅助子工具(在 M2 中)只给客观数据,不给"合理价格"

12. ❌ **不让 AI 编造叙事故事**(v0.5 新增): AI 在叙事场景幻觉风险最高,严格禁止"叙事链条推演"型输出

### 架构关键判断(v0.5 更新)

1. **决策状态机和日志引擎仍是业务骨架** — AI 全部不可用时,产品依然完整可用
2. **L1 研究素材库是新的"数据资产层"** — 与业务模块并列,价值随使用时间复利增长
3. **AI 辅助层是"可拔插"的** — AI 通过 MCP 暴露能力,但**不写入任何结论性字段**
4. **数据流单向**: 数据源 → Python 取数 → 写入 L1 → 业务模块按需调用 L1 → 用户审阅 → 用户填结论 → 写 Journal。**AI 任何环节都不能跳过用户直接写 Journal**
5. **风险护栏 M7 是"硬约束层"** — 触发规则/禁区时,Checklist 提交会被拦截,强制用户写"例外说明",该说明永久记入 Journal
6. **架构上预留"AI 完全关闭"开关** — Cursor/Claude 不可用时,通过 CLI 仍能完成: 录入素材 / 填 Checklist / 写 Journal / 跑监控 / 跑复盘
7. **portfolio.yaml 仍是人类可读的持仓主存** — 但 risk_rules / personal_redlines / L1 元数据等单独 YAML 文件,避免主文件过大
8. **叙事识别能力嵌入而非独立(v0.5 新增)** — "叙事信号包"嵌入 M4 监控,"叙事错过模式扫描"嵌入 M5 复盘助手,**不独立成 M8 模块**。理由: 与 M4/M5 既有逻辑一脉相承(监控=看信号 / 复盘=从历史学习),共享调度器和报告生成器
9. **叙事数据流是"客观汇集 → 用户判断阶段"严格单向(v0.5)** — 系统**只**呈现六维信号矩阵和历史可比案例,**绝不**写 `narrative_stage` 字段(AI 在叙事场景幻觉风险最高,强制硬约束)

## 五、九大核心设计原则(v0.4 在 v0.3 七条基础上新增两条架构级原则)

### 1. 流程优先,AI 次之(原则置换)

> **v0.2 的"AI-Native"被推翻**。新原则:**产品骨架是用户的执行流程,不是 AI**。

- 流程(Checklist + 状态机 + 日志)永远可用,即使 AI 全部下线
- AI 是"加速器"而不是"发动机":有它更高效,没它也能跑
- 反面教材:把"巡检报告"作为 AI 的输出物——这等于把产品命脉交给 AI

### 2. 决策权与结论权 100% 在用户

> 在 v0.2"决策权在用户"基础上**进一步收紧**:**结论性字段也禁止 AI 写入**。

- AI 输出分析、数据、信息汇总——但**不写**分类、判断、置信度
- 任何形如"我判断"、"我建议"、"我认为"的句式,AI 不能用
- AI 的所有输出都必须是"中性陈述"(列出事实、引用原文、汇总数据)

**强制实现**: Journal/巡检报告/复盘报告的"分类"、"行动建议"、"置信度"等字段,在 schema 层标记为 `user_filled: true`,系统拒绝接受 AI 直接写入。

### 3. 事实/推理/结论 三段分离(强制)

> 来自 baseline-05,在 v0.3 升级为**产品级架构约束**,不仅是"AI 协作礼仪"。

每条信息的存储必须打上来源标签:

```yaml
- type: fact         # 事实(数据 + 出处 + 时间戳)
  source: akshare
  data: {...}
  
- type: reasoning    # 推理(谁推的、基于什么)
  author: user | ai
  basis: "..."
  
- type: conclusion   # 结论(必须是 user 写的)
  author: user       # ← 强制为 user
  confidence: high | medium | low
  reversal_conditions: [...]
```

报告生成器在渲染时必须用三种不同视觉标记区分(📊 事实 / 🧠 推理 / ⚖️ 结论),并显示作者。

### 4. 上下文持久化优先(v0.2 保留并加强)

系统必须长期保存:

- 当前持仓 / 成本 / 仓位
- **每一次决策的完整快照**(数据、推理、结论、市场环境)
- **每次巡检结论 + 巡检时的事实快照**(为复盘提供基线)
- 用户对每个标的的"个人 thesis"(可版本化,thesis 演进可追溯)
- 用户的"历史认知错误模式"(由复盘引擎沉淀)

**核心理念**: 3 年后翻出来,所有判断的上下文还能被完整还原。

### 5. 个人数据是真正的护城河(v0.3 新增)

> 通用 AI 的弱点是不知道你的历史。你的执行日志独一无二。

- 不依赖任何"通用 AI 模型的进步"作为产品价值的增长点
- 产品价值随**用户使用时间**线性增长(日志越多 → 错误模式越清晰 → 检查项越精准)
- 数据所有权 100% 在本地(YAML + SQLite,不上云)

### 6. 数据要诚实,而非"够用就行"(v0.2 原则被推翻)

> v0.2 的"数据轻、推理重"被推翻。

- 数据本身要**准确、可追溯**(每个数据点必须有 source + timestamp)
- 宁可缺数据,也不接受"AI 编出来的看似合理的数据"
- AI 不能联网时,必须明确标注"训练记忆,可能过时"
- 计算指标(ROE/FCF/估值分位等)用 Python 在客观数据上算,不让 AI 算

### 7. 文档驱动开发(v0.2 保留)

每个功能在写代码前先有文档(场景 → 设计 → 接口)。

- 仅一人开发,不能靠"口口相传"
- 长期演进的项目,文档是唯一可靠的"项目记忆"
- AI 协作开发时,文档是给 AI 的最佳 brief

### 8. 信息源可信度分级(v0.4 新增,架构级硬约束)

> 所有进入系统的数据必须打可信度等级标签,显示给用户,影响 AI 引用时的处理。

| 等级 | 来源类型 | 例子 | 用途 |
|---|---|---|---|
| **S** | 监管披露 | 公司公告(巨潮)、交易所、证监会、央行、统计局 | 决策依据 |
| **A** | 结构化金融数据库 | Tushare/AKShare/同花顺 iFinD/Wind 接口 | 决策依据(注意数据修订) |
| **B** | 主流财经媒体 / 卖方研报 | 上证报、证券时报、Bloomberg、券商研报 | 参考依据 |
| **C** | 社区/自媒体/股吧 | 雪球帖、知乎专栏、淘股吧、微信公众号 | 仅作情绪与思路参考 |
| **D** | AI 推测/汇总 | LLM 输出、Web Search 经 AI 改写的内容 | **必须明确标注,不作决策依据** |

**实现规则**:

1. L1 入库时,每条素材必填 `tier` 字段
2. 决策 Checklist 中,引用某条素材时,系统显示其 tier 标签
3. 当用户用 C/D 级素材作为"主要依据"时,系统弹出确认("这是 C/D 级信息源,是否仍要作为主要依据?")
4. 复盘时统计: 不同 tier 的素材在用户历史决策中的"准确率"(用真实收益反向校验)

### 9. 决策快照"冻结即不变"(v0.4 新增,数据架构硬约束)

> 决策当下取的数据,必须冻结存储,以后不能被新数据覆盖。

**为什么必须做**:

- 财报有修订(预披露 → 正式 → 修订版)
- 研报会更新(分析师改了预期)
- 网页会变(雪球帖被删、公告被撤)
- 历史价格数据可能复权方式不同

如果决策时取了一个版本,复盘时被新版本覆盖,**复盘就失真**了 — 你以为你当时是基于错误数据做的决策,其实只是因为数据变了。

**实现规则**:

1. M3 Journal 在创建时,把所有引用的数据 **冻结快照** 写入 SQLite
2. L1 中的原始数据可以更新(追加版本),但 Journal 中的快照只读
3. Journal 字段命名: `data_snapshot`(冻结的) vs `data_reference`(指向 L1 的当前版本)
4. 复盘时,默认读 `data_snapshot`,如果用户主动想看"今天的最新版本",显式调用 `data_reference`,且报告中明确区分两者
5. 数据源如果有重大修订,作为新记录追加到 L1,**不覆盖**原版本

## 六、与现有工具的差异化对比(v0.3 更新)

| 工具 | 强项 | 弱项 | 我们做不做 |
|---|---|---|---|
| **同花顺 / 东财 / 雪球** | 实时行情、社区、基础数据 | 无决策日志、无 Checklist、无个性化复盘 | 行情我们不做,**决策与复盘**是我们的核心 |
| **直接用 Cursor / ChatGPT 对话** | 灵活、AI 强 | 没有持仓上下文,每次重复输入;数据需手动喂;**结论不可追溯,容易接受 AI 幻觉** | 我们把对话沉淀为可追溯的 Journal,且严格限制 AI 的结论权 |
| **Notion / Excel 投资日志** | 灵活、个人化 | 无强制 Checklist、无状态机、无监控、无数据集成 | 我们做**强结构 + 自动数据接入**的 Journal |
| **Wind / iFinD** | 数据全、专业 | 贵(机构级)、上手成本高、无个人决策流程 | 不抢机构市场 |
| **量化平台(聚宽/米筐)** | 回测、自动化 | 偏短线/技术面,不适合长线;不解决"主观决策的纪律化" | 不做量化 |
| **理杏仁 / 萝卜投研** | 数据 + 估值工具 | 工具型,无决策流程闭环 | 我们对接数据但补全"流程闭环" |

### v0.3 的独特生态位

> **「散户的投资飞行日志:把每个决策的依据、过程、结果都结构化记录下来,用真实收益反向迭代决策模式。AI 是数据秘书,不是决策者。」**

类比航空业:
- 飞行员不需要"AI 替我飞"
- 飞行员需要"Checklist + Flight Log + Debrief 机制"
- 这套机制让普通人也能把事故率压到极低

我们要做的就是投资决策版的这套机制。

## 七、核心场景预览(v0.4 在 v0.3 基础上增补,按"研究/决策/持有/复盘"四种状态)

> v0.4 关键认知: 在 v0.3 的"决策/持有/复盘"三态基础上,**新增"研究时刻"作为日常常态**。
> 研究素材的积累是产品的底层资产,不是某次决策的附属动作。

### 四种状态的需求对比(v0.4)

| 状态 | 频率 | 风险等级 | 用户需要什么 | AI 的角色 |
|---|---|---|---|---|
| **研究时刻**(v0.4 新增) | **日常持续** | 无直接风险 | **素材录入 + 标签 + 检索**(L1 研究素材库) | 自动拉取/格式化,辅助检索,**不下结论** |
| **决策时刻** | 低频 | 高 | **强制 Checklist + 数据辅助 + 风险护栏拦截 + 写 Journal** | 取数据、按模板整理,**不下结论** |
| **持有时刻** | 高频 | 低 | **规则化监控 + 异常推送 + 市场状态画像** | 几乎不参与,系统按规则触发 |
| **复盘时刻** | 周期性 | 中 | **历史数据汇总 + 错误模式扫描 + 策略画像** | 汇总信息、检索 Journal,**不下结论** |

### 场景 0: 研究时刻 — L1 素材积累(v0.4 新增,日常常态)

**状态**: 任何时候,持续积累

**子场景 0.1: 自动入库(系统后台运行)**
- 定时同步 AKShare/Tushare/东财的财务/估值/行情增量数据
- 抓取持仓 + 观察池标的的新公告、新研报
- 抓取关注板块的产业新闻、政策文件
- 同一数据点只入库一次,版本化追加(不覆盖)

**子场景 0.2: 手动录入(用户主动)**
- 路径 A: 看到一篇好文章 → 复制链接 + 摘要 + 关联标的/标签 → CLI 一行命令入库
- 路径 B: 拿到一份调研纪要 / 付费研报 PDF → 上传 + 元数据 → 入库
- 路径 C: 关注的某大牛(冯柳、林园、雪球大V等)发了观点 → 截图 + 粘贴原文 + 关联标的 → 入库
- 路径 D: 自己写的笔记/调研感受 → CLI 或 Web 表单写入 + 关联标的 → 入库

**子场景 0.3: 主动检索(无决策压力)**
- "上次完美世界相关的素材有哪些"
- "去年我录入的关于游戏行业的文章"
- "冯柳今年关于消费的所有观点"

**输出**: L1 数据库持续增长。每条素材有完整元数据,可被未来任何决策/巡检/复盘引用。

**AI 角色**:
- ✅ 帮你从粘贴的原文中抽取标题/作者/关键标签建议
- ✅ 检索 L1 时按相关性排序
- ❌ 不评价"这篇文章观点对不对"
- ❌ 不替你下"哪条素材该作为决策依据"的结论

### 场景 1: 决策时刻 — 选股与观察池(v0.4 明确观察池机制)

**状态**: 标的从"看见" → "进入观察池(watching)" → "深度评估" → 决定是否进入持仓

**子场景 1.1: 进入观察池(轻量 Checklist)**
- 输入: 某标的进入视野(可能来源: M6 候选池 / 自己看研报 / 大牛提及 / 板块扫描)
- 轻量 Checklist 必填:
  - 初步 thesis 草稿(1-3 段,可粗糙)
  - 关注理由分类(估值 / 业绩拐点 / 事件催化 / 行业景气 / 大牛持仓 / 其他)
  - 待跟踪的 1-3 个关键指标(下次评估时重点看)
  - `emotion_tag`(冷静/兴奋/被FOMO驱动)
- AI 辅助: 拉取基础信息(主营业务、最新财报摘要、当前估值分位)
- 状态机: `unknown → watching`

**子场景 1.2: 观察池月度评估**
- 系统自动: 每月对观察池中所有标的做一次轻量轮询
- 检查: 当初设定的"待跟踪指标"是否有新数据?是否触发了升级/剔除条件?
- 用户决策(三选一):
  - 继续观察(更新跟踪指标)
  - 升级 → 触发完整建仓 Checklist
  - 剔除 → 写"剔除原因",从观察池移除(留 Journal 记录,用于未来复盘"我剔除掉的有没有大涨")

**子场景 1.3: 观察池升级 → 持仓(走场景 2 完整建仓 Checklist)**

**输出**: 观察池数据 + 轻量 Journal 记录 + 月度轮询报告

---

### 场景 2: 决策时刻 — 建仓(v0.4 增补 emotion_tag + 风险护栏拦截)

**状态**: 从观察池 → 持仓 (`watching → holding`)

- 强制 Checklist 填写:
  - thesis(为什么买?核心逻辑 3 段以内)
  - **目标价**(基于什么估值方法?**v0.4: 调用 M2 估值辅助子工具查 PE/PB 分位 + 同业对比 + PE 锚定测算**)
  - 止损/减仓线(逻辑破坏的具体表现是什么?)
  - 反转条件(什么发生时改变判断?)
  - 机会成本对比(vs 沪深 300 / 中证科技,这笔钱不投这个能投什么?)
  - 置信度(高/中/低)
  - 已识别风险点
  - `emotion_tag`(v0.4 新增,枚举: calm / anxious / excited / fearful / greedy / FOMO,1 秒选完)
- AI 辅助: 从 L1 拉取相关素材;调用估值辅助子工具
- 系统自动: 抓取决策当日的市场环境快照
- **🛡️ 风险护栏拦截(v0.4 新增,M7 介入)**:
  - 检查本次建仓后是否触发: 单标的仓位超限 / 板块集中度超限 / 个人禁区
  - 触发 → 弹出确认: 必须写"为什么这次例外",该说明永久记入 Journal
  - 未触发 → 直接通过

**输出**: 一条不可篡改的"建仓 Journal",写入决策日志;持仓状态机 `watching → holding`

### 场景 3: 持有时刻 — 日常监控(v0.4 扩容: 加市场状态画像 + 板块异动告警)

**状态**: 持仓中,无主动操作

- **不需要 AI 介入**,系统按规则运行:

**3.1 个股层面(v0.3 已有)**
- 财报披露日历(到点提醒)
- 价格阈值告警(到目标价/止损线触发)
- 重大事件抓取(政策、监管、高管变动)
- 估值分位异常(超过历史 90 分位或低于 10 分位)

**3.2 板块层面(v0.4 新增,M4 扩容)**
- 持仓板块的成交量异动(成交萎缩 / 异常放量)
- 持仓板块 vs 大盘的相对强度变化(风格切换确认信号)
- 板块整体 ROE / 估值分位的月度变化

**3.3 市场状态画像(v0.4 新增,周更)**
- 当前指数水位 + 估值分位
- 风格在哪(成长/价值/防御)
- 资金面(两融 / 北向 / ETF 资金流)
- 历史可比时点参考

**3.4 风险护栏运行时检查(v0.4 新增,M7 监控)**
- 仓位规则: 当前持仓是否超过单标的 / 单板块上限
- 机会成本(MVP-2): 各持仓 vs 基准累计差距是否触发告警
- 回撤(MVP-2): 整体账户 / 单标的从高点回撤是否超阈值

**3.5 叙事信号事件触发(v0.5 新增)**
- 当某只持仓/观察池标的同时触发"价格放量突破 + 卖方研报激增 + 海外同业上涨"等组合条件时, **自动生成叙事信号包**并推送
- 推送形式: 邮件/微信,内容为"信号矩阵已生成,请查看",**不**推送"该标的进入加速期"等结论
- 用户主动: 任何时候可手动 `inv narrative <code>` 生成信号包

**核心理念**: 持有期最大的敌人是"焦虑性操作"。系统**减少**而非**增加**用户的注意力消耗。
告警发送形式: 邮件 / 微信(Server 酱),只发"信号"不发"建议"。

### 场景 4: 决策时刻 — 持仓巡检(v0.4 增补 L1 素材调用 + emotion_tag)

**状态**: 周期性(月/季)或事件触发的深度审视

- AI 辅助(只填事实):
  - 拉取最新财报四维度数据(ROE / FCF / 市占 / 核心叙事的事实变化)
  - 拉取上次巡检结论 + 当时的事实快照,做对比
  - 列出新发生的相关事件
  - **从 L1 检索本次巡检周期内新录入的、关联本标的的所有素材**(v0.4 新增)
- 用户填空(结论部分):
  - 四象限分类(低估逻辑还在 / 等风格切换 / 周期低谷 / 价值陷阱)
  - 行动建议(持有 / 加仓 / 减仓 / 退出)
  - 置信度 + 反转条件
  - 与原 thesis 对比: thesis 是否还成立?哪些假设被验证?哪些被证伪?
  - **thesis 是否需要演进 (v0.4 强化)**: 如果需要,生成新版本 `thesis_version`,系统会在 M5 复盘时扫描"thesis 频繁修改且每次都放宽预期"的反常模式
  - `emotion_tag`(v0.4 新增)
- 风险护栏检查: 若行动是"加仓",同场景 2 走 M7 拦截流程

**输出**: 巡检报告 Journal(事实部分 AI 填,结论部分用户填)

### 场景 5: 决策时刻 — 卖出(v0.4 增补 emotion_tag)

**状态**: 从持仓 → 平仓 (`holding → closed`)

- 强制 Checklist 填写:
  - 卖出原因分类(7 类: 逻辑破坏 / 估值过热 / 目标价到 / 止损 / 换股 / 风格切换 / 其他)
  - 本笔收益归因(thesis 验证程度? 择时贡献? 运气成分?)
  - 教训沉淀(下次类似情境怎么做?)
  - `emotion_tag`(v0.4 新增)
- AI 辅助: 拉取本笔交易期间的关键数据(指数对比、个股走势、相关事件);从 L1 检索本笔持有期间的相关素材
- 系统自动: 计算 vs 沪深300/中证科技的相对收益
- **🛡️ 风险护栏检查**: 若卖出原因为"止损" + 同时大盘处于恐慌区间,触发"恐慌止损"红线提醒(可继续,但需写例外说明)

**输出**: 一条"平仓 Journal",写入决策日志;同时触发该标的的"完整生命周期报告"生成

### 场景 6: 复盘时刻 — 周期性复盘(v0.5 再增补叙事错过模式扫描)

**状态**: 月/季/年的回顾

- AI 辅助:
  - 汇总周期内的所有 Journal
  - 计算各标的的实际收益、相对收益、持有期
  - 按规则扫描错误模式(基于规则,不是 AI 判断):
    - 频繁出现的"卖飞"事件
    - 反复出现的"低估值陷阱"判断
    - thesis 被证伪但未及时减仓的标的
    - **(v0.4)** 不同 `emotion_tag` 下的决策与最终收益的相关性
    - **(v0.4)** 不同 tier(S/A/B/C/D)信息源在你历史决策中的"准确率"
    - **(v0.4)** thesis 频繁修改且方向都是"放宽预期"的反常模式
  - **(v0.4) 策略画像**(年度): 你在哪些行业 / 哪些类型(估值修复/景气拐点/事件驱动)上胜率高,哪些低
  - **(v0.5) 叙事错过模式扫描**: 详见场景 7
- 用户填空:
  - 错误归因(每个识别出的错误,根因是什么?)
  - 教训沉淀(转化为下次 Checklist 的强制项)
  - 投资策略迭代(是否需要调整持仓结构 / 风格 / 个人交易规则 / 个人禁区清单)
  - **(v0.5)** 是否需要把识别出的"错过模式"对应的能力圈/禁区做调整(如取消"不投半导体设备")

**输出**: 复盘报告 + 个人化 Checklist 更新 + 个人禁区清单更新

### 场景 7: 叙事时刻 — 信号包查看与阶段判断(v0.5 新增)

**状态**: 任何时候(主动触发) / 月度自动 / 事件触发(场景 3.5)

> 这是 v0.5 引入的全新场景,与"决策/持有/复盘"三态并列,本质是"**用客观信号反偏见地观察叙事拐点**"。

**子场景 7.1: 主动查看信号包**
- 触发: 用户对某只标的(持仓/观察池/外部关注)请求生成信号包
  - CLI: `inv narrative <code>`
  - 或在 Cursor 中通过 MCP 工具 `get_narrative_signal_pack` 请求
- 系统输出: 六维度信号矩阵 + 历史可比案例检索 + L1 中关联本标的近 90 天素材列表
- AI 角色: **只**填事实/数据/历史对比,**绝不**给阶段判断或"是否值得买"

**子场景 7.2: 月度自动生成**
- 调度器每月对所有持仓 + 观察池中标的自动生成信号包
- 入库: 历次信号包永久存档(可在 M5 复盘时回看"上次信号包后我做了什么")
- 推送: 邮件/微信摘要,告知"已生成 N 个信号包,请查看",**不**推送结论

**子场景 7.3: 事件触发自动生成**
- 触发条件(规则化,无 AI 判断):
  - 价格放量突破历史平台 + 卖方研报激增(过去 30 天 vs 12 月均值 ≥ 3 倍)
  - 海外同业过去 6 个月涨幅 ≥ 50% + 国内对应标的尚未启动
  - 公司业绩超预期幅度 ≥ 30% + 一致预期上修
- 触发后自动生成信号包 + 推送

**子场景 7.4: 阶段判断与决策联动**
- 用户阅读信号包后,在系统内填 `narrative_stage_assessment`(强制必填):
  - `stage`: 萌芽 / 验证 / 加速 / 主升 / 共识 / 衰退
  - `reasoning`: 必须引用六维信号中至少 3 项作为理由
  - `reversal_signals`: 如果你判错了,什么发生时改变判断?
  - `decision_implication`: 此判断对建仓/持有/卖出决策的影响?
- 该填写记入 Journal,与对应决策(如随后的建仓 Checklist)双向链接
- 强拦截规则(决策 4: A): 建仓 Checklist 中如果该标的有信号包,**必须先填阶段判断**才能继续

**关键约束(v0.5 硬约束)**:
- ❌ AI **绝不**写 `stage` 字段
- ❌ AI **绝不**给"建议加仓/减仓"
- ❌ AI **绝不**编造"叙事链条故事"(只列事实)
- ✅ AI 可以辅助: 从 L1 检索相关素材、计算同业对比、列出海外预演数据
- ✅ 所有信号包输出**必须包含"反偏见工具,非水晶球"声明**(避免被误用)

**输出**:
1. 叙事信号包 Markdown 报告(存档到 SQLite + 文件系统)
2. 用户的阶段判断记录(Journal)
3. 与后续 Checklist 的双向链接

## 八、MVP 范围(v0.5 在 v0.4 基础上 M4/M5 子模块增补)

### MVP = **L1 研究素材库 + 7 个业务模块(v0.5 在 M4/M5 内嵌叙事子模块)**, 拆 **MVP-1 (核心决策闭环) + MVP-2 (增强能力)** 两期落地

> ✅ 决策来源:
> - 第五轮决策(Q1-Q7,全部按 PM 推荐确认):
>   - Q1: 拆分热点(M4 吸收市场状态画像+板块异动,M6 重命名为候选池)
>   - Q2: 估值辅助嵌入 M2(不独立成模块)
>   - Q3: M7 风险护栏拆二期(MVP-1: 仓位规则+个人禁区, MVP-2: 机会成本/回撤/集中度)
>   - Q4: 加观察池子状态 + emotion_tag(都加)
>   - Q5: L1 研究素材库独立为数据基础设施层
>   - Q6: 信息源分级 + 快照冻结都写入 01 作为架构级硬约束
>   - Q7: MVP 拆二期(MVP-1 12-15 周 + MVP-2 10-14 周)
> - 第六轮决策(v0.5,Q1-Q5,全部按 PM 推荐确认):
>   - Q1: 叙事识别**嵌入 M4/M5 子模块**(不独立 M8)
>   - Q2: MVP-1 **不放**叙事子模块,叙事进 MVP-2(避免 MVP-1 工期失控)
>   - Q3: 信号矩阵采用**六维度全集**(基本面/产业链/资金面/关注度/估值/价格行为)
>   - Q4: 阶段判断**强制必填且强拦截**(决策前未填则无法提交建仓 Checklist)
>   - Q5: 海外同业映射在 MVP-2 简化版交付(手动维护映射表),不做完整产业链图谱

### 各模块详细职责(v0.4)

#### L1: 研究素材库(Research Library) — v0.4 新增,数据基础设施

> 不是"业务模块",而是与业务模块并列的**数据基础设施层**。所有业务模块都依赖它。

- **自动入库 Pipeline**:
  - 持仓 + 观察池标的的财务/估值/价格增量同步
  - 公告 / 研报 PDF 抓取(东财 / 巨潮)
  - 雪球 / 股吧 / 淘股吧热帖快照(限定标的相关)
  - 关注的产业新闻、政策文件
  - **同一数据点只入库一次,版本化追加(不覆盖)**
- **手动录入(用户主动)**:
  - 复制链接 + 摘要 + 关联标的/标签 → CLI 一行命令入库
  - 上传 PDF/截图 + 元数据 → 入库
  - 大牛观点(粘贴/截图) + 关联标的 → 入库
  - 个人笔记 / 调研感受 → 入库
- **元数据标准(强制)**:
  - `id` / `source` / `tier`(S/A/B/C/D) / `timestamp` / `related_stocks` / `tags` / `author` / `content_type`(data/doc/note/post)
- **检索能力**:
  - 按标的 / 时间 / 标签 / 作者 / 可信度筛选
  - MCP 工具暴露给 AI 检索(只读)
- CLI 命令(MVP-1 最小集):
  - `inv lib add --type=doc --url=<url> --stocks=<code> --tags=...`
  - `inv lib search --code=<code> --tier=S,A --since=2026-01`
  - `inv lib show <id>`
- CLI 命令(MVP-2 增强): 高级标签 / 邮件转发录入 / 简易 Web UI

#### M1: 持仓状态机(Position State Machine)

> 不是简单的"持仓列表",而是带状态流转规则的状态机。v0.4 明确 `watching` 为独立子状态。

- **状态**: `unknown` → `watching`(观察池) → `holding`(持有) → `inspecting`(巡检中) → `adjusting`(调仓) → `closed`(已平仓)
- **状态转换必须触发对应的 Checklist + Journal 记录**
- **`watching` 子状态(v0.4 强化)**:
  - 进入: 轻量观察 Checklist(初步 thesis + 关注理由 + 待跟踪指标 + emotion_tag)
  - 月度自动轮询: 检查 watching 中所有标的的待跟踪指标
  - 升级/剔除: 用户决策(升级走完整建仓 Checklist,剔除写"剔除原因")
- 数据载体: `portfolio.yaml`(主存) + SQLite(历史与快照)
- 支持 `type: core | swing` 区分长线主仓与热点副仓
- CLI 命令: `inv pos list / show <code> / move <code> --to=<state> / watch add <code>`
- MCP 工具: `get_portfolio`, `get_position_detail`, `get_position_history`, `get_watchlist`

#### M2: Checklist 引擎(Checklist Engine)— v0.4 增补估值辅助子工具 + emotion_tag

> v0.3 核心模块。每个决策动作的"强制规范"。v0.4 内嵌"估值辅助"和"情绪标签"。

- 内置 Checklist 模板:
  - **轻量观察 Checklist(v0.4 新增)**: thesis 草稿 / 关注理由 / 待跟踪指标 / emotion_tag
  - **建仓 Checklist**: thesis / 目标价 / 止损线 / 反转条件 / 机会成本 / 置信度 / 风险点 / **emotion_tag(v0.4)**
  - **巡检 Checklist**: 四维度判断 / 与上次对比 / 与 thesis 对比 / 分类 / 行动 / 反转条件 / **emotion_tag(v0.4)** / **thesis 是否需要演进**
  - **卖出 Checklist**: 卖出原因 / 收益归因 / 教训沉淀 / **emotion_tag(v0.4)**
- **估值辅助子工具(v0.4 新增,Checklist 内嵌)**:
  - PE/PB 历史分位(过去 5 年)
  - 同业对比(同行业 TOP 标的 PE/PB 中位数)
  - 一致预期 EPS / 净利润 → PE 锚定测算
  - 当前价 vs target_price / stop_loss 的距离
  - ❗ 只给数据,不给"合理价格"结论,target_price 必须用户填
- **emotion_tag 枚举字段(v0.4 新增)**: `calm` / `anxious` / `excited` / `fearful` / `greedy` / `FOMO`(1 秒选完)
- 强制必填校验: 留白则保存失败
- 模板版本化: 通过复盘沉淀的新检查项,会作为模板演进
- 历史填表对比: 新表填写时,能看到该标的上次同类填表的内容
- CLI 命令: `inv checklist start --type=watch|buy|inspect|sell --code=<code>`
- MCP 工具: `get_checklist_template`, `get_filled_checklist_history`, `get_valuation_helper`(数据查询,不下结论)

#### M3: 决策日志引擎(Journal Engine)

> v0.3 核心模块。投资行为的"飞行日志"。v0.4 增加 L1 引用追踪。

- 每个 Checklist 提交后自动生成一条 Journal 记录
- Journal 字段:
  - `id`, `timestamp`, `position_code`, `action_type`(watch/buy/inspect/adjust/sell)
  - `checklist_filled`(填写的 Checklist 内容,含 emotion_tag)
  - `market_snapshot`(决策当日的指数水位、板块估值分位、宏观指标)
  - `data_snapshot`(决策依据的具体数据,带 source + tier + timestamp,**冻结快照**)
  - `l1_references`(v0.4 新增: 本次决策引用的 L1 素材 id 列表)
  - `ai_assist_log`(本次决策用了哪些 AI 辅助,AI 给了什么信息)
  - `risk_guardrail_check`(v0.4 新增: 触发了哪些 M7 规则,例外说明)
  - `conclusion`(用户写的结论,必须 `author: user`)
- **不可篡改**: 提交后只能追加修正记录,不能修改原记录
- **快照冻结**: `data_snapshot` 一旦写入,L1 后续版本更新不会回填覆盖
- CLI 命令: `inv journal list / show <id> / search --code=<code>`
- MCP 工具: `search_journal`, `get_journal_detail`(只读)

#### M4: 规则化监控引擎(Monitor)— v0.4 扩容市场状态/板块异动, v0.5 新增叙事信号包子模块

> v0.3 核心模块,v0.4 显著扩容, v0.5 再嵌入叙事识别子模块。持有期的"自动哨兵 + 市场状态雷达 + 叙事拐点观察镜"。

**MVP-1 包含**:
- **个股层**(v0.3 已有):
  - 财报披露日历 / 价格阈值 / 事件触发 / 估值分位异常
- **巡检日历**: 月度 / 季度巡检到期提醒

**MVP-2 扩容(v0.4 新增)**:
- **板块层(主仓刚需)**:
  - 持仓板块的成交量异动
  - 持仓板块 vs 大盘的相对强度变化
  - 板块整体 ROE / 估值分位的月度变化
- **市场状态画像(周更)**:
  - 当前指数水位 + 估值分位
  - 风格在哪(成长/价值/防御)
  - 资金面(两融 / 北向 / ETF 资金流)
  - 历史可比时点参考(基于规则,不基于 AI 判断)

**MVP-2 新增子模块: ★ 叙事信号包(Narrative Signal Pack, v0.5)**:
- 六维度信号矩阵(全部可量化):
  - A 基本面: 业绩超预期/收入结构/毛利拐点/在手订单/客户结构/研发产出
  - B 产业链: 上游订单/行业 CapEx/技术节点切换/海外同业预演(MVP-2 简化版: 手动维护映射表)
  - C 资金面: 公募持仓环比/北向/龙虎榜/ETF 流向/大宗交易/高管增减持
  - D 关注度: 卖方研报数量/媒体提及/雪球热度/调研频率/百度指数
  - E 估值: PE/PB/PS 分位/PEG/vs 同业溢价折价
  - F 价格行为: 距上次新高时间/成交量异动/超额收益变化/突破形态
- 历史可比案例检索(L1 集成): 从 L1 检索"过去出现过类似信号组合的案例 + 后续走势",**不下结论**
- 触发方式:
  - 主动: `inv narrative <code>`
  - 月度自动: 调度器对所有持仓+观察池标的生成
  - 事件触发: 规则化触发条件满足(详见场景 7.3)
- 推送: 邮件/微信,只发"信号包已生成"提示,**不发结论**
- 用户填: `narrative_stage_assessment`(stage / reasoning / reversal_signals / decision_implication),**强制必填且强拦截**(决策 4 确认)
- 所有信号包输出**必须包含"反偏见工具,非水晶球"声明**

- 触发方式: 邮件 / Server 酱微信
- **严格原则**: 监控只发"信号",不发"建议"
- CLI 命令: `inv monitor list / test / market` / **`inv narrative <code>` (v0.5)**
- MCP 工具: `get_narrative_signal_pack`(只读,只返回客观信号 + 历史对比)
- 后台运行: 调度器定时跑(每日 / 每周 / 财报日 / 月初叙事扫描)

#### M5: 复盘助手(Reviewer)— v0.4 增补策略画像 + emotion/tier 相关性, v0.5 新增叙事错过模式扫描

> v0.3 核心模块。把"账户盈亏"转化为"判断模式的迭代"。v0.5 新增子模块,把"错过"也纳入复盘资产。

**MVP-1 包含**(v0.3 已有):
- **收益归因**: 按标的 / 按板块 / 按持有期 / 按决策类型(主仓 vs 热点)
- **vs 基准对比**: 累计收益 vs 沪深 300 / 中证科技 / 行业指数
- **基础错误模式扫描**(基于规则,不基于 AI):
  - "X 次卖飞"(平仓后 3 个月内涨幅 > 20%)
  - "Y 次低估值陷阱"(基于低 PE 买入,持有 1 年以上跑输沪深 300)
  - "Z 次 thesis 被证伪但未及时减仓"

**MVP-2 扩容(v0.4 新增)**:
- **策略画像(年度)**: 你在哪些行业/类型上胜率高、哪些低
- **emotion 相关性**: 不同 emotion_tag 下的决策与最终收益的相关性
- **信息源 tier 准确率**: 不同 tier 的素材在你历史决策中的"准确率"
- **thesis 演进健康度扫描**: thesis 频繁修改且每次都"放宽预期"的反常模式
- **个人禁区例外回测**: 触发禁区但选择继续的决策,最终收益统计

**MVP-2 新增子模块: ★ 叙事错过模式扫描(Missed Narrative Pattern Scan, v0.5)**:
- 周期性(季度/年度)扫描全市场过去 12 个月涨幅 > 80% 的板块/个股
- 排除已持仓 + 观察池中的标的 = "你错过的"
- 对每个错过案例反查:
  - 涨之前 6 个月叙事六维信号何时共振
  - L1 中是否已有相关线索(关联素材列表)
  - 与你能力圈、个人禁区(`personal_redlines.yaml`)的关系
- 长期沉淀输出: **你个人的"错过模式画像"**
  - 总是错过哪类叙事(技术驱动?海外预演?事件驱动?)
  - 覆盖盲区在哪些行业
  - 哪些"个人禁区"实际代价高昂(可能需要调整)
- 用户审阅后,可主动调整 `personal_redlines.yaml`(经用户填写确认,**AI 不自动修改**)

- 用户参与: 报告生成后,用户对每个识别出的错误填写"归因 + 教训",系统沉淀为下次 Checklist 的强制项
- CLI 命令: `inv review --period=month|quarter|year` / **`inv review missed --period=year` (v0.5)**
- MCP 工具: `summarize_period_journals`, `get_missed_pattern_report`(汇总信息,不下结论)

#### M6: 候选池(Candidate Pool)— v0.4 重命名,弱化日级,强化事件驱动

> 由 v0.3 的"热点信息汇总"重命名而来。**弱化日级炒题材,强化事件驱动 + 信息汇总**。

- 输入触发:
  - 催化事件(政策、并购、技术突破、产业拐点)
  - 板块异动(M4 监控告警的二级输出)
  - 用户主动加入(从 L1 检索中、从大牛动态中、从研报中)
- 输出内容(严格限定):
  - ✅ 事件原文摘录 + 出处 + 时间
  - ✅ 相关标的清单(基于明确的业务关联规则)
  - ✅ 这些标的的客观数据(PE / 估值分位 / 近期涨跌幅 / L1 中已有的素材列表)
  - ❌ **不**评估弹性
  - ❌ **不**预测涨跌
  - ❌ **不**给买入建议
- 频率: **周 / 月级,不做日级**(避免诱发短线频繁交易)
- 用户决定: 是否把某只标的纳入观察池(走 M1 状态机的 watching 流程)
- CLI 命令: `inv pool list / show <code>`
- MCP 工具: `fetch_event_brief`, `list_related_stocks`(基于规则,不基于 AI 推理)

#### M7: 风险护栏(Risk Guardrails)— v0.4 新增

> 投资专业领域的核心能力,在 v0.3 完全缺失。v0.4 补齐。

**MVP-1 包含(必须)**:
- **仓位规则**(`risk_rules.yaml` 配置):
  - 单标的最大仓位 / 单板块集中度上限 / 整体仓位水平
  - 提交 Checklist 时实时检查,触发则要求"例外说明"
- **个人禁区清单**(`personal_redlines.yaml` 配置):
  - 例: 不投我不懂的行业 / 不报复性加仓 / 不在恐慌时止损 / 不追自己看不懂的热点
  - 用户可自由增删
  - 提交 Checklist 时实时检查,触发则强制写"为什么这次例外"
  - **例外说明永久记入 Journal**(复盘时统计"例外的实际收益")

**MVP-2 扩容**:
- **机会成本跟踪**: 每只持仓 vs 沪深300/中证科技 累计差距告警(跑输 20-30 个百分点触发"机会成本巡检")
- **回撤告警**: 整体账户 / 单标的从高点回撤超阈值告警
- **集中度管理**: 板块相关性管理(看似分散实则集中的识别)

- CLI 命令: `inv risk rules / show / test --plan=<checklist_id>`
- MCP 工具: `get_risk_rules`, `check_position_against_rules`(只读,不下结论)

| 维度 | v0.3(已废弃) | v0.4 合计 | v0.5(当前) |

- 多了"错过模式画像"这个反偏见复盘工具
- L1 的价值密度大幅提升(叙事信号包是 L1 最大的消费者之一)

#### 关于工期长度的判断

> ⚠️ 7-9 个月业余时间是个**很长但合理的承诺**。

但拆成 MVP-1 / MVP-2 后:
1. MVP-1 完成时(约 3-4 个月),核心决策闭环已经能跑,价值产出已经开始
2. MVP-2 是渐进增强,可以根据 MVP-1 使用反馈调整优先级

5. **(v0.5)叙事子模块的工期投入是值得的**: 投资生涯中错过 1 次叙事级行情的代价,远高于 3-4 周开发时间。如果资源紧张,可以先把"叙事信号包"做完(MVP-2A,约 2-3 周),"错过模式扫描"延后(MVP-2B)
