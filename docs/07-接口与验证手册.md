## 一、本手册的目的

从 **H1 正式编码起**，每完成一个可调用功能，必须同步交付一份 **接口说明 + 验证步骤**（存放在 `docs/manual/`）。

目标读者演进路径：

| 阶段 | 读者 | 手册写法 |
|---|---|---|
| MVP-1 编码期 | 你（PM/验收人） | 逐步操作 + 预期输出 + 失败样例 |
| MVP-1 dogfood | 家人/朋友试点 | 加「为什么做这一步」+ 截图位 |
| MVP-2+ | 外部接入者 / SaaS 用户 | 收敛为公开 **用户使用文档** |

**原则**：不懂系统设计的人，只看 `docs/manual/` + 复制粘贴命令，也能完成验证。

## 二、四层文档（接口 + 字段）

| 层 | 路径 | 回答的问题 |
|---|---|---|
| **操作手册** | `docs/manual/H*.md` | 命令怎么敲、输出长什么样 |
| **字段字典** | `docs/manual/ref-*.md` | **每个字段怎么填、可选值有哪些** |
| **配置模板** | `config/*.example.yaml` | 带行内中文注释的可复制示例 |
| **Go schema** | `internal/core/store/sqlstore/schema/` | 表结构 ↔ struct；IDE 悬停看注释 |

> 仅看 H* 手册知道「接口做什么」；**要动手填数据**时必须打开 **ref-*** 或 example。

## 三、三类接口面

| 类型 | 说明 | 文档章节模板 |
|---|---|---|
| **CLI** | `inv` 子命令；人类可读 + `--json` 机器可读 | §命令 / §参数 / §stdout / §stderr / §退出码 |
| **MCP** | Cursor 调用的只读 tool（H7） | §tool 名 / §input JSON / §output JSON / §错误 |
| **gRPC** | Go ↔ Python data-worker（H3） | §rpc / §request / §response / §grpc 错误码 |

MVP-1 以 **CLI 为主**；MCP / gRPC 在对应 H 完成时按同一模板追加。

## 四、每功能交付物清单（Definition of Done for Docs）

完成一个功能项 **代码 + 文档** 才算 Done：

| # | 交付物 | 路径 |
|---|---|---|
| 1 | 接口说明页 | `docs/manual/{里程碑}-{功能 slug}.md` |
| 2 | 自动化测试 | `go test` 或 `*_test.go`（与手册「自动化验证」节对应） |
| 3 | 手册索引更新 | 本文档 §五 状态表 |
| 4 | 示例数据 | `docs/manual/fixtures/` 或引用 `config/*.example.yaml` |
| 5 | 决策追溯 | 若行为来自 `docs/06`，手册头部 `> 决议：Dxx` |
| 6 | **字段字典**（若有新字段/表） | `docs/manual/ref-*.md` + `schema/*.go` + `config/*.example` 中文注释 |

**禁止**：只有代码没有手册；只有手册没有可复制的命令；**有新字段却没有 ref 说明**。

## 五、接口说明页标准结构

> 模板文件：[`docs/manual/_template-功能接口.md`](manual/_template-功能接口.md)

每篇必须包含：

1. **一句话**：这个功能解决什么用户问题
2. **前置条件**：环境变量、目录、依赖命令、示例数据是否已初始化
3. **命令/API 签名**
4. **参数表**（名称、必填、类型、默认值、说明）
5. **成功输出示例**（完整 stdout 或 JSON，非摘要）
6. **失败输出示例**（至少 2 种：参数错误 + 业务校验失败）
7. **退出码**
8. **边界与已知限制**（含 AI 边界、MVP 未实现项）
9. **手动验证步骤**（逐步 numbered list）
10. **自动化验证**（`go test ./...` 或具体测试名）
11. **关联文档**（03/02/06 章节链接）

## 七、全局验证环境（所有手册共用）

### 6.1 一次性准备

```powershell
# 仓库根目录
cd C:\Users\qs\Desktop\workspace\investment-assistant

# 编译 CLI
go build -o bin/inv.exe ./cmd/inv

# 运行时数据（不进 Git）
$env:DATA_ROOT = ".\data"
$env:IA_ACCOUNT_ID = "default"

# 模板配置（首次 init 会复制到 data/.../state/）
$env:IA_CONFIG_ROOT = ".\config"
```

### 6.2 干净环境重置（慎用）

```powershell
Remove-Item -Recurse -Force .\data\accounts\default -ErrorAction SilentlyContinue
```

重置后重新跑 `inv doctor`，会自动 migrate + 从 `config/*.example.yaml` 初始化 state。

### 6.3 推荐验收顺序

```text
go test ./...                    # 自动化
bin/inv.exe version              # H0
bin/inv.exe doctor --scope library
bin/inv.exe doctor --scope portfolio   # H1（空库 + example 预期失败）
# … 每个新功能按 manual 文档追加
```

### 6.4 退出码约定（MVP-1 逐步统一）

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 一般错误（参数、IO、校验失败） |
| 2 | 数据不一致（`doctor` 失败）—— **H2 起统一** |

> H0/H1 当前 cobra 失败均 exit 1；H2 起 `doctor` 业务失败改 exit 2（见 03 §十C.1）。
