## 二、数据架构总原则

### 1. 人类可读优先

用户需要长期维护和审阅的状态，优先放 YAML。

典型包括：

- 当前持仓
- 观察池
- 风险规则
- 个人禁区
- 叙事阈值配置
- 海外同业映射

### 2. 行为流水进 SQLite

所有会持续增长、需要查询、统计、复盘的行为数据进入 SQLite。

典型包括：

- Checklist 提交记录
- Journal
- lot
- 巡检记录
- 监控事件
- 风险例外
- 复盘报告元数据
- L1 素材元数据

### 3. 原文和附件进文件系统

大文本、PDF、HTML 快照、截图、上传附件不直接塞进 SQLite。

SQLite 保存元数据和路径，文件系统保存原文。

### 4. 决策快照冻结

Journal 中的 `data_snapshot` 一旦生成，不允许被 L1 后续更新覆盖。

后续复盘时必须区分：

- `decision_snapshot`：当时看到的事实
- `current_data`：复盘时看到的新事实

### 5. 所有数据必须有 source / tier / timestamp

任何进入系统并可能影响决策的数据，都必须记录：

| 字段 | 说明 |
|---|---|
| `source` | 来源 |
| `tier` | S/A/B/C/D |
| `timestamp` | 原始发布时间或采集时间 |

## 三、存储分层草案

### Layer A：YAML 配置与状态

| 文件 | MVP-1 | 内容 |
|---|---|---|
| `portfolio.yaml` | 是 | 当前持仓主状态 |
| `watchlist.yaml` | 是 | 观察池 |
| `risk_rules.yaml` | 是 | 仓位、集中度、整体仓位、单一 thesis 暴露阈值 |
| `personal_redlines.yaml` | 是 | 个人禁区 |
| `data_sources.yaml` | 是 | 数据源配置与 tier 默认值 |
| `narrative_signals.yaml` | MVP-2 | 叙事六维信号阈值 |
| `overseas_peers.yaml` | MVP-2 | 海外同业映射 |

### Layer B：SQLite 结构化数据

| 表 | MVP-1 | 内容 |
|---|---|---|
| `checklist_submissions` | 是 | 所有 Checklist 提交记录 |
| `journals` | 是 | 建仓、加仓、卖出、规则变更等 Journal |
| `lots` | 是 | 建仓 / 加仓批次，用于 lot 级归因 |
| `library_items` | 是 | L1 素材元数据 |
| `library_links` | 是 | L1 素材与标的、Journal、Checklist 的关联 |
| `inspection_records` | 是 | 持仓巡检记录 |
| `monitor_events` | 是 | 监控触发事件 |
| `risk_exceptions` | 是 | warning / hard block / exception 记录 |
| `review_reports` | 是 | 月度 / 季度复盘报告元数据 |
| `data_snapshots` | 是 | 决策快照 |
| `narrative_signal_packs` | MVP-2 | 叙事信号包 |
| `narrative_stage_assessments` | MVP-2 | 用户叙事阶段判断 |
| `missed_pattern_reports` | MVP-2 | 错过模式扫描 |

### Layer C：文件系统

| 目录 | MVP-1 | 内容 |
|---|---|---|
| `library/docs/<year>/` | 是 | PDF、研报、公告附件 |
| `library/snapshots/<year>/` | 是 | HTML / 网页快照 |
| `library/uploads/<year>/` | 是 | 用户上传文件、截图、笔记附件 |
| `reports/<year>/reviews/` | 是 | 复盘 Markdown 报告 |
| `reports/<year>/inspections/` | 是 | 巡检 Markdown 报告 |
| `reports/<year>/narrative/` | MVP-2 | 叙事信号包报告 |

## 四、阶段 3 优先讨论顺序

建议按下面顺序推进：

1. 先定 YAML 文件：`portfolio.yaml`、`watchlist.yaml`、`risk_rules.yaml`、`personal_redlines.yaml`。
2. 再定 SQLite 核心表：`journals`、`checklist_submissions`、`lots`、`data_snapshots`。
3. 再定 L1：`library_items`、文件存储、去重、source/tier。
4. 再定 M4/M5：`monitor_events`、`review_reports`、`risk_exceptions`。
5. 最后定 MVP-2 叙事相关表。
